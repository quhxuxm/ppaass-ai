# 最高吞吐历史基线与复测说明

> **状态：历史基线，不是当前性能承诺。** 本文件中的数值随 2026-08-09 的报告实现提交保存，
> 未记录对应的硬件、操作系统、提交 SHA、网络条件和完整运行配置。当前代码、默认端口和
> 并发扫描策略均已变化，因此不能将这些数值用于发布验收或版本间性能比较。

## 当前测试实现

最大吞吐测试由 `integration-tests` 的 `max-throughput` 命令执行，通过
`run-tests.sh` 启动。它分别测量 TCP/UDP 直连基线，以及可用的 TUN、HTTP CONNECT、
SOCKS5 TCP 和 SOCKS5 UDP Relay 端到端链路：

```text
客户端 -> Agent -> Proxy Entry -> 回显目标 -> Proxy Entry -> Agent -> 客户端
```

测试客户端按成功发送和接收的有效 payload 计算上行、下行及合计 Mbps；不包含 IP、TCP、
SOCKS、加密及协议帧开销。因此它反映的是应用层端到端有效吞吐，不是物理网卡带宽，也不能
拆分为客户端→Agent、Agent→Entry、Entry→目标三段的速率。

当前脚本默认值如下：

| 项目 | 当前默认值 |
| --- | --- |
| Agent / Proxy 地址 | `127.0.0.1:7080` / `127.0.0.1:8080` |
| TCP / UDP 回显目标 | `127.0.0.1:9091` / `127.0.0.1:9092` |
| 并发扫描 | 从 `1` 开始，最高 `128`；逐级翻倍 |
| 每级持续时间 | 10 秒；预热 2 秒，稳定等待 1 秒 |
| TCP / UDP payload | 65,536 / 1,200 字节 |
| 可持续失败率上限 | 1.0% |

只有失败率不高于上限的阶段能够参与峰值判定。若测试 TUN，目标流量必须实际经过指定的
接口；回环目标通常会绕过 TUN，不应为它记录 TUN 成绩。

## 复测当前版本

先按[测试指南](TESTING.md#4-本地端到端测试)启动测试拓扑，再在仓库根目录运行：

```bash
START_CONCURRENCY=1 MAX_FAILURE_RATE=1.0 \
  ./run-tests.sh max-throughput 128 10 65536
```

若验证 TUN 路径，显式指定实际承载流量的 TUN 接口：

```bash
TUN_INTERFACE=utun8 START_CONCURRENCY=2 MAX_FAILURE_RATE=0.5 \
  ./run-tests.sh max-throughput 256 15 65536
```

每次运行会在当前目录生成带时间戳的 HTML、JSON 和 Markdown 报告，例如
`max-throughput-report-YYYYMMDD-HHMMSS.{html,json,md}`。JSON 是合并或重渲染报告的原始
输入，应与其余两个文件一并归档。

新的可比较基线至少应记录：Git 提交 SHA、运行日期、CPU/内存/OS、网络接口与链路、Agent/
Entry/目标部署位置、配置、扫描参数、失败率阈值，以及原始 HTML/JSON/Markdown 产物。不要
把不同机器、目标或 payload 的结果直接相除得出“性能回归”。

## 已归档的旧基线

下面数据保留为早期实现的参考快照。其测试使用旧 Agent 地址 `127.0.0.1:11080`、并发档位
`8、16、32、64、128`，与当前默认设置不同；所有速率均为应用层合计峰值。

| 接口 | 结果 | 合计峰值 | 最佳并发 | 备注 |
| --- | --- | ---: | ---: | --- |
| TCP 直连基线 | 完成 | 60,849.57 Mbps | 64 | 峰值未确认 |
| UDP 直连基线 | 完成 | 1,870.45 Mbps | 8 | 峰值确认 |
| TUN 端到端 | 未完成 | — | — | 目标走 `lo0`，未经过 TUN |
| HTTP CONNECT 端到端 | 完成 | 21,537.05 Mbps | 32 | 峰值确认 |
| SOCKS5 TCP 端到端 | 完成 | 18,669.79 Mbps | 16 | 峰值确认 |
| SOCKS5 UDP Relay 端到端 | 完成 | 956.10 Mbps | 32 | 峰值确认 |

旧报告中，HTTP CONNECT、SOCKS5 TCP 和 SOCKS5 UDP Relay 的同并发保留率分别约为
37.60%、34.82% 和 65.79%。这些比例只描述当时的单次环境，不能推断当前版本的性能或作为
CI 阈值。

## 判读原则

- 将直连基线与端到端模式在**相同并发档位**比较；不要用两者各自峰值计算损失。
- 将上行、下行、合计、失败率和 P95 RTT 一起判断；只提高总 Mbps 可能掩盖错误或延迟恶化。
- TUN 结果必须有路由证据；未穿过指定 TUN 接口的流量应标记为未完成。
- 性能数据需要在受控环境重复采样后才适合设为发布门槛。
